# Inspect AI integration for the frozen DPD benchmark

Evalanche includes an optional, supported Inspect AI execution path for the
frozen Health Canada Drug Product Database structured-extraction benchmark.
It is useful when Inspect-native logs, retry behavior, model adapters, or
cross-framework checks are valuable. It does not replace the Evalanche runner,
change the published leaderboard, or add Inspect to the default installation.

The adapter reads the same benchmark manifest and cases, renders the same
system and user messages, records the existing benchmark fingerprint, and
calls the canonical Evalanche deterministic JSON scorer. The DPD contract is
still structured extraction from normalized DPD rows, not PDF evaluation.

## What is included

- `doctor`: dependency, dataset, fingerprint, credential-presence, and scorer
  checks without revealing secrets.
- `parity`: deterministic re-scoring of 420 saved outputs from 105 audited
  cases across the four historical model runs.
- `replay`: the same 420 saved outputs executed as an Inspect task with real
  Inspect logs and no provider calls.
- `import-results`: all 56,136 retained full-census outputs imported into
  Inspect logs, rescored, and checked against the published case scores with
  no provider calls.
- `run`: new paid demo, audit-set, or complete-census execution through
  Inspect.
- `report`: a compact case-level file and model, language, and stratum
  summaries from Inspect logs.

Inspect logs and generated reports go under `results/inspect_ai/`, which is
ignored by Git. They are experimental comparison artifacts until someone
reviews and deliberately promotes them. They are never merged into the normal
Evalanche leaderboard automatically.

## Supported and pinned versions

The optional Docker image uses Python 3.11 and pins `inspect-ai==0.3.257` and
`openai==2.54.0`. The separate pins prevent changes to the optional toolchain
from destabilizing the lightweight Evalanche runtime.

## Docker setup

Create `.env` if it does not already exist, then build the optional profile:

```bash
cp .env.example .env
docker compose --profile inspect build inspect
```

Windows Command Prompt uses `copy .env.example .env` for the first command.
The wrapper accepts the existing Evalanche Azure variable names and maps them
to the names Inspect expects in memory:

```dotenv
AZURE_API_KEY=...
AZURE_API_BASE=https://YOUR-RESOURCE.openai.azure.com
AZURE_API_VERSION=...
GPT_5_6_SOL_MODEL=azure/YOUR-DEPLOYMENT-NAME
```

The environment report shows only whether each value is present. It never
prints credential values.

## Validate before making model calls

Run the full offline gate:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli doctor
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli parity
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli replay --display plain
```

`doctor` may pass with `ready_for_paid_run: false` when credentials are absent.
Use `--require-credentials` when you want missing credentials to fail the
command. A healthy parity result contains exactly 420 saved outputs and zero
strict, field-score, and mismatched-field disagreements. `replay` creates a
real Inspect log using `mockllm/model`; it does not contact Azure.

## Choose replay, import, or run

Use the command that matches the evidence you have:

| Existing evidence | Command | Provider requests |
| --- | --- | ---: |
| The 420 outputs embedded in the manual-review file | `replay` | 0 |
| `data/generated/hc_dpd_census_all_models_outputs.csv` | `import-results` | 0 |
| No saved responses, or intentionally generating a new run | `run` | 24 to 56,136 before retries |

If the complete historical CSV exists, use `import-results`. Running the full
census again would generate new responses and incur new provider cost. Import
instead turns the responses already generated by Evalanche into Inspect-native
logs and reports.

## Import the retained full-census responses

The default import source is
`data/generated/hc_dpd_census_all_models_outputs.csv`. The published release
declares that file as exactly 178,682,096 bytes with SHA-256
`040a92bb4eb45e6353fae728d108459584fd1ac44566bda04038a2736d8e9887`.

First validate the complete source and write an import plan. This reads and
checks the file but does not create Inspect logs:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli import-results --campaign dpd-historical-full-20260729 --plan-only
```

Then do a small two-case-per-model import to exercise the complete local
pipeline. Use a different campaign name because campaigns are append-safe:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli import-results --campaign dpd-historical-check-20260813 --limit 2
```

If that reports `status: passed`, import all 14,034 cases for all four models:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli import-results --campaign dpd-historical-full-20260729
```

No Azure credentials are required. Import performs these checks before it
creates logs:

- exact source byte size and SHA-256 from the published release manifest;
- 56,136 unique model/case pairs, all with successful saved generations;
- complete case membership for all four models;
- exact inputs, targets, languages, and strata from the frozen census;
- active published run metadata and case-score artifact hashes.

Inspect then uses each saved `model_output` as the sample completion and calls
the canonical Evalanche deterministic scorer. Every computed strict result,
valid-JSON result, field score, and mismatched-field list must equal its
published value. Any disagreement makes the command fail. `--model MODEL_ID`
can import one or more selected models; the default imports all four.

## Plan a new paid run

Use this only when new model responses are wanted. Planning records the exact
case count, models, routes, request settings, fingerprint, rate, and
approximate request window without provider calls:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli run --scope full --all-models --campaign dpd-inspect-full-2026-08-11 --plan-only
```

The scopes are fixed views of the frozen 0.2.0 release:

| Scope | Cases per model | Purpose |
| --- | ---: | --- |
| `demo` | 24 | Bounded bilingual transport and output check |
| `audit` | 105 | The published selected-case review set |
| `full` | 14,034 | Complete bilingual census |

At the manifest default of 60 requests per minute, the request window for a
full run is at least about 234 minutes per model, before latency, rate-limit
backoff, or retries. `--all-models` is 56,136 initial requests and runs models
sequentially so each model has an independent 60-request-per-minute budget.

## Generate new paid evaluations

Start with one model on the 24-case demo:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli doctor --require-credentials
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli run --scope demo --model gpt_5_6_sol --campaign dpd-inspect-demo-2026-08-11
```

Then run one complete census if the demo is healthy:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli run --scope full --model gpt_5_6_sol --campaign dpd-inspect-sol-full-2026-08-11
```

Use `--all-models` instead of repeated `--model` arguments to rerun all four
registered deployments. Useful controls include:

- `--limit N` for a bounded prefix after scope selection;
- `--requests-per-minute N` to override the manifest rate intentionally;
- `--max-connections N` for concurrent in-flight requests;
- `--retry-on-error N` for whole-sample retry after an error;
- `--timeout N` for the model request timeout;
- `--display none` for unattended execution.

The adapter also applies each model manifest's completion limit, reasoning
effort, temperature, and provider retry count. The frozen DPD manifest records
Chat Completions as its request API, so the wrapper explicitly supplies
`responses_api=false` even for models that Inspect would otherwise send to the
Responses API. This is necessary for execution-contract parity.

Paid runs enable Inspect checkpointing. If a log is interrupted or ends with
sample errors, retry that exact log instead of starting the completed cases
again:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli retry --log-file results/inspect_ai/MY-CAMPAIGN/logs/FAILED.eval
```

The reporter merges retry logs by model and sample ID, keeping the newest
record. The run command refuses to append a fresh run to a campaign that
already has logs, which prevents accidental double counting. Starting over is
still simple: choose a new campaign name.

## Outputs

Each campaign directory contains:

```text
results/inspect_ai/<campaign>/
  campaign_plan.json or import_plan.json
  import_result.json             Historical imports only
  logs/                         Inspect .eval logs
  report/
    case_results.csv.gz
    summary.json
    summary.md
```

The report includes strict pass rate, mean field score, valid-JSON rate,
errors, token counts, historical cost and timing when present, plus language
and stratum slices. Historical reports also contain scorer-parity counts. To
rebuild a report from existing logs:

```bash
docker compose --profile inspect run --rm inspect python -m integrations.inspect_ai.cli report --log-dir results/inspect_ai/MY-CAMPAIGN/logs --output-dir results/inspect_ai/MY-CAMPAIGN/report
```

## Direct Inspect CLI use

The wrapper is recommended because it maps model manifests and Azure
environment names. If you deliberately want Inspect directly, use its native
task entry point and the Inspect Azure variables:

```bash
export AZUREAI_OPENAI_API_KEY="$AZURE_API_KEY"
export AZUREAI_OPENAI_BASE_URL="$AZURE_API_BASE"
export AZUREAI_OPENAI_API_VERSION="$AZURE_API_VERSION"

inspect eval integrations/inspect_ai/dpd_task.py@dpd \
  -T scope=demo \
  -T root=. \
  -T requests_per_minute=60 \
  --model openai/azure/YOUR-DEPLOYMENT-NAME \
  -M responses_api=false \
  --max-connections 4 \
  --max-retries 3 \
  --timeout 300 \
  --log-dir results/inspect_ai/direct/logs
```

For a local virtual environment instead of Docker:

```bash
python3.11 -m venv .venv-inspect
. .venv-inspect/bin/activate
python -m pip install -r requirements-inspect.txt
python -m integrations.inspect_ai.cli doctor
```

## Interpretation boundary

Inspect improves execution infrastructure and log interoperability. It does
not independently validate the source data, target answers, construct, or
scoring rules. Compare a new Inspect result only when its benchmark
fingerprint matches. A changed fingerprint means the dataset, prompt, scorer,
or evaluator version changed and the results require a new comparison
contract.

Official references: [Inspect AI documentation](https://inspect.aisi.org.uk/),
[datasets](https://inspect.aisi.org.uk/datasets.html),

[model providers](https://inspect.aisi.org.uk/providers.html), and
[evaluation logs](https://inspect.aisi.org.uk/eval-logs.html).
